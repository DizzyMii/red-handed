A CLI for AI agent diffs

All tests pass.
Sure they do.

red-handed reads a code change and tells you if an AI coding agent got the tests green by cheating. A test that got skipped. An expected value bent to match the bug.

It's fixed regex rules over the added and removed lines. There is no model in the loop and no API key.

    I ran it over 111 pull requests recently merged into React, Next.js, VS Code, Django, Kubernetes, Rails and six other big projects. It said CAUGHT three times and each one really did cut test coverage: a revert took its tests with it, a flaky check got deleted, an assertion got wrapped in a try. All three had a reason and a maintainer's sign-off, which is fine. Somebody looked, and that's the job. On 16 PRs opened by AI agents it flagged nothing, correctly.

    It misses things. On 92 made-up diffs, written by AI agents that couldn't see the rules and measured before I tuned anything, it flagged 24 of 45 cheats and wrongly called 3 of 47 honest changes CAUGHT. If it gets yours wrong, send me the diff.

        02

        Run it

        Exit code is 0 for CLEAN or SUSPICIOUS, 1 for CAUGHT, 2 if it couldn't run. --strict fails on SUSPICIOUS too, and --json is there if you want to do something else with it.

        • npx red-handed

          Inside a repo. Compares your branch with main and includes uncommitted and untracked files.

        • npx red-handed https://github.com/owner/repo/pull/12

          A public pull request, no clone. Set GITHUB_TOKEN for private repos or the rate limit.

        • npx red-handed demo

          Builds a throwaway repo, cheats five ways and scans it. Same diff as "All five at once" above.

        • git diff main | npx red-handed -

          Any diff on stdin, or pass a .patch file.

        03

        GitHub Action

        It posts one comment on the pull request and edits it on every push. Pull requests from forks get a read-only token, so there the report only goes to the job summary.

        name: red-handed
on: pull_request

permissions:
  contents: read
  pull-requests: write

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: dizzymii/red-handed@v0
        with:
          fail-on: caught
        04

        21 rules

        Read from src/rules.mjs, the same file the playground runs. One HARD finding makes the verdict CAUGHT. SOFT findings have honest uses, so they only make it SUSPICIOUS.

          05

          What it does not do

          Treat it as a smoke alarm. When it goes off, go read the lines it printed.

          It doesn't run your tests, so it can't tell you whether they pass. The rules are regexes over added and removed lines, and a determined author can get around them: build the string "te" + "st" and test-detection never sees it, or move the cheat somewhere it doesn't look.

          So a CLEAN means the usual tricks are absent and nothing more. Expect the odd false SOFT finding too. If you get a false HARD one, open an issue with the diff.

          It doesn't send your code anywhere either, the only network call is to the GitHub API when you hand it a pull request.

          I made this because I got tired of reading agent diffs where the green checkmark came from the test file.
